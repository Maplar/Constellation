# 文件夹与来源调色盘拆分设计

## 目标

将前端 UI 校准台现有的“统一调色盘”拆为两个并列入口：

- **文件夹颜色**
- **来源颜色**

拆分只改善入口、目标选择和预览语义，不改变颜色事实源，不实施真实前后端读写，也不允许各视图保存独立颜色覆盖。

## 设计原则

1. 文件夹与外部来源属于不同颜色事实源，主界面不再把三类目标混入同一列表。
2. 两个调色盘复用同一套色环、安全色、HEX、预设色和最近颜色组件，避免重复交互。
3. 本地引用不提供单独调色入口，始终继承目标文件所在文件夹颜色。
4. URL 与 AI 都属于外部来源集合，共用来源调色盘与持久化模型，但通过分段切换、挖空图案和文案明确区分。
5. 主流程保持精简；RGB/HSL、透明度、对比度、安全色强度和颜色历史管理继续放在设置的“高级取色”。

## 独立表面入口

“独立表面”区域将原有单个“统一调色盘”入口替换为两个同级入口：

| 入口 | 副标题 | 作用 |
|------|--------|------|
| 文件夹颜色 | 彩虹文件夹与本地引用 | 修改真实文件夹颜色并预览继承效果 |
| 来源颜色 | URL 与 AI 来源集合 | 修改外部来源集合颜色并预览引用效果 |

点击入口后直接打开对应调色盘，不先显示二级类型选择页。

## 文件夹颜色调色盘

### 目标列表

只显示真实文件夹，不显示 URL、AI 或单独的本地引用项。每个目标展示：

- 文件夹颜色圆点
- 文件夹名称
- 必要的父级路径

### 颜色事实源

正式实现对应：

```text
.constellation/folders.json
```

前端 UI 校准台只模拟目标切换、草稿取色、应用和取消，不写入文件。

### 同步预览

文件夹颜色草稿同步预览：

- 文件树中的文件夹颜色
- 继承该颜色的本地文件引用胶囊
- 本地引用连接竖线
- 本地来源片段预览框
- 知识树中的文件或子树节点
- 图谱中的本地文件节点与显式引用边

应用按钮文案为“应用到文件夹”。

## 来源颜色调色盘

### URL / AI 分段切换

来源调色盘顶部使用紧凑分段按钮：

```text
URL | AI
```

切换后只显示当前类型的来源集合：

- URL 页只列 URL 来源集合。
- AI 页只列 AI 来源集合。

URL 与 AI 的颜色仍存入同一个来源集合事实源，不因 UI 拆分而建立两套业务模型。

### 目标表达

每个来源集合展示：

- 来源集合颜色圆点
- URL 挖空窄体 `U` 或 AI 挖空 `AI`
- 集合名称
- 简短类型说明

来源图案只表达类型，颜色只表达来源集合。图片、视频、音频、PDF、网页或混合内容继续使用独立媒体徽标，不占用来源颜色。

### 颜色事实源

正式实现对应：

```text
.constellation/source-collections.json
```

前端 UI 校准台只模拟状态，不创建或修改真实来源集合。

### 同步预览

来源颜色草稿同步预览：

- 对应类型的引用胶囊
- 来源连接竖线
- 通用来源片段预览框
- 图谱来源节点
- 显式来源边

URL 与 AI 的预览分别使用各自图案，不互相改色。应用按钮根据分段状态显示：

- “应用到 URL 来源集合”
- “应用到 AI 来源集合”

## 共用取色核心

两个调色盘共用以下组件和行为：

- 专业色相环
- 中央饱和度与明度区域
- 原始色与 UI 安全色双预览
- HEX 输入
- 彩虹预设色
- 最近使用颜色
- 恢复默认、取消和应用操作

共用组件只处理颜色草稿与取色计算；入口标题、目标列表、图案、预览项目、按钮文案和事实源说明由当前调色盘上下文提供。

## 草稿与切换规则

1. 每个文件夹、URL 来源集合和 AI 来源集合分别保留自己的校准台临时草稿。
2. 切换目标时恢复该目标尚未应用的草稿。
3. 在来源调色盘中切换 URL/AI 时，两侧草稿互不覆盖。
4. 点击“应用”只更新当前目标的校准台演示状态。
5. 点击“取消”恢复当前目标最近一次已应用颜色。
6. 关闭存在未应用修改的调色盘时，显示“放弃修改 / 继续编辑”确认。
7. 切换到另一个独立表面时遵循相同的未应用修改确认规则。

## 空状态

- 文件夹颜色没有可选目标时，提示“当前知识库还没有可调色的文件夹”。
- URL 或 AI 没有来源集合时，提示当前类型尚无来源集合，并提供“新建来源集合”校准按钮。
- “新建来源集合”只展示后续交互入口，不在本轮创建真实文件或数据。

## 校准台范围

本轮只调整：

- 独立表面入口
- 两个调色盘的标题、目标列表和上下文
- URL/AI 分段切换
- 同步预览内容
- 草稿、应用、取消与关闭确认的静态交互
- README 与 AGENTS 中对调色盘入口和职责的描述

本轮不实施：

- `.constellation/folders.json` 真实读写
- `.constellation/source-collections.json` 真实读写
- 来源集合真实创建、删除或重命名
- Tauri API、Rust 服务或正式 React 组件
- 新的数据模型或视图级颜色覆盖

## 校准验收

1. “独立表面”中显示两个并列入口，不再出现“统一调色盘”入口。
2. 文件夹调色盘只显示文件夹目标。
3. 来源调色盘使用 URL/AI 分段切换，并只显示当前类型的来源集合。
4. 两个调色盘的色环与基础取色能力视觉一致。
5. 文件夹颜色预览包含文件树，来源颜色预览不伪装成文件夹。
6. URL 与 AI 保持各自的挖空图案，切换和改色互不覆盖。
7. 应用按钮文案准确说明当前修改对象。
8. 所有预览继续遵守“一处颜色事实源，多视图继承”的规则。
9. Light、Dark、Warm 三套主题下均无系统原生白底按钮、原生选择框或不适配滚动条。
10. 校准台不产生真实工作区文件写入。
