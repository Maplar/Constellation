# 快捷便签续写与文字感悟设计

## 范围

本设计仅用于前端 UI 校准和后续实现计划，不在本阶段实施真实文件写入、编辑器模型或后端预测服务。

## 目标

- 用户观看视频、阅读资料或临时思考时，可以关闭快捷便签后继续原记录。
- 用户可以同时保留多个未整理草稿，但不会因系统错误预测而写入错误文件。
- 快捷便签保持轻量，不演变为第二套文件管理器。
- 用户可以对选中文字添加下划线或独立感悟，不与 Markdown 块引用混淆。

## 组件语义

### Markdown 块引用

- 用于摘录、原话或需要保留来源语气的内容。
- 底层继续使用标准 Markdown `>`。
- 视觉使用左侧实线、浅背景、圆角和内边距。
- 块引用与感悟组件互相独立，不默认嵌套。

### 下划线

- 编辑工具栏增加普通 `U` 下划线按钮。
- 只提供单一下划线，不增加荧光标记、双下划线或波浪线。
- 底层使用可读的内联 HTML `<u>文字</u>`，不引入私有 Markdown 语法。

### 文字感悟

- 用户选中文字后点击“感”，在选区末尾生成 `感₁` 上标。
- 点击上标后，在原文附近显示宽约 `360–480px` 的横向悬浮卡片。
- 卡片包含感悟正文、编辑和删除操作。
- 悬停只高亮标记，点击才展开卡片。
- 感悟不改变原文段落层级，也不嵌套进 Markdown 块引用。
- 底层优先使用 Markdown 脚注保存原文锚点与感悟正文，正式实现时由结构化编辑器和 Markdown AST 维护。

## 快捷便签生命周期

### 全局独立暂存区

- 快捷便签不归属于当前专题、当前文件夹或当前编辑文件。
- 当前专题不参与快捷便签的默认保存位置或强制分类；分类由用户在整理确认时决定。
- 文件栏在最后一个真实文件之后提供独立的“快捷便签”折叠区，作为全局暂存和整理入口。
- 文件区与快捷便签区只使用“文件”“快捷便签”分区标签和细分隔线区分；快捷便签区不使用外层卡片边框或独立配色，全部复用文件栏 Design Tokens。
- 快捷便签底层仍保存为真实 Markdown 文件，不使用数据库、隐藏正文或第二套事实源。
- 推荐在知识库根目录使用可见的 `快捷便签/` 暂存目录；界面将其提升为独立区显示，不在普通文件树中重复展示。
- 用户确认整理后，通过应用内目录选择器将 Markdown 文件移动到目标真实文件夹，并保留稳定 `constellation_id`。
- 移动完成后，该文件退出快捷便签暂存区，作为普通 Markdown 笔记显示。

### 多个未整理草稿

- 系统允许存在多个带“未整理”状态的快捷便签。
- 同一时间只有一个“活动草稿”，快捷便签入口默认打开它。
- 其他未整理草稿进入轻量待整理列表，不自动合并、不自动归档。

### 打开行为

- 只有一个未整理草稿时，直接续写，并在标题栏显示“正在续写：标题 · 最后编辑时间”。
- 存在多个草稿且活动草稿明确时，默认打开活动草稿。
- 多个草稿都在近期编辑、无法可靠判断时，不进行强预测；显示紧凑草稿选择层。
- 选择层显示标题、最后编辑时间、首行预览和“新便签”入口。
- 用户始终可以通过标题栏的 `+` 明确新建便签。

### 弱预测原则

预测只决定默认聚焦项，不得自动合并、移动或改写内容。

默认优先级：

1. 用户手动固定为活动草稿的便签。
2. 当前会话刚关闭、仍为未整理状态的便签。
3. 最近编辑的未整理便签。
4. 出现时间或上下文冲突时，停止预测并显示选择层。

### 结束与纠错

- 关闭窗口只隐藏便签，不结束草稿。
- “整理完成”会移除“未整理”状态，并使其退出活动草稿。
- 新建便签不会自动把旧草稿标为已整理。
- 如果用户误续写，可将本次打开后新增的内容“一键拆为新便签”。
- AI 可以建议两篇内容相关，但未经确认不得合并正文或改变文件路径。

## 校准台 UI

文件栏顺序调整为：

1. 知识库标题与新建入口。
2. “文件”标签和真实 Markdown 文件树。
3. 最后一个文件之后的“快捷便签”可折叠区，显示活动草稿和未整理数量。
4. 可选专题。
5. 默认折叠的同步与留痕状态。

删除以下校准内容：

- “全库入口”分组。
- “00 收件箱”文件夹及相关组件。
- 全局“附件”文件夹及相关组件。

Constellation 不提供邮件接收工作流。附件仍可通过具体 Markdown 笔记的图片/附件操作插入，并使用工作区相对路径保存；它不是文件栏中的全局收件栏目。

快捷便签标题栏从左到右显示：

1. 用户填写的便签标题。
2. `未整理 n ▾` 草稿切换入口。
3. `+` 新便签。
4. 转磁贴。
5. 关闭。

正文选中文字后出现轻量浮动工具：

- `U` 下划线。
- `感` 添加感悟。

感悟上标与长条卡片使用中性色和当前主题 Design Tokens，不复用引用来源颜色，避免被误认为本地、URL 或 AI 引用。

## 验收标准

1. 两个以上未整理草稿时，用户能够看见当前续写对象并切换。
2. 系统不需要假装准确预测用户的随机意图。
3. 新建、续写、整理完成和拆分误写都有明确入口。
4. 关闭便签后再次打开不会无提示创建零散文件。
5. 下划线、块引用和感悟具有不同语义与视觉。
6. 感悟卡片不挤压正文布局，不与块引用嵌套。
7. 本阶段只更新 UI 校准台和产品文档，不实施真实前后端。
8. 文件栏不存在“全库入口”“收件箱”或全局“附件”栏目。
9. 快捷便签作为最后一个真实文件之后的全局独立暂存区，整理确认后移动到用户选择的真实文件夹。
10. 文件区和便签区只通过标签与分隔线区分，不使用两个不同颜色或额外外框。
